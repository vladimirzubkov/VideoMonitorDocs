Presets (Runners & Miners)

Runners and Miners share the same preset bank model. FFmpeg options (Runners) and yt-dlp options (Miners) live in two places:

LayerWhere it livesWhen it changes
Row draftrunner.ffmpeg_args / miner.ytdlp_argsImmediately as you type in the options field
Preset bank[app] → ffmpeg_presets / yt_dlp_presets (+ labels)Only on explicit save paths (see below)

Typing in the field does not update the global preset bank by default. That prevents accidental overwrites when you click another preset slot.

Settings​

Open Settings → Coordination (near Process files on FFmpeg change and Allow runner FFmpeg preset chain):

OptionConfig keyDefault
Auto save runner preset on editauto_save_runner_preset_on_editoff
Auto save miner preset on editauto_save_miner_preset_on_editoff

Each tab is independent. The legacy option Save preset names on mouse click only was removed from the UI and is forced to false in config sanitization.

Editing options in the field​

flowchart TD
  edit[Edit in options field] --> rowOnly[Update runner/miner row only]
  rowOnly --> autoOn{Auto-save ON for this tab?}
  autoOn -->|No| noBank[Preset bank unchanged]
  autoOn -->|Yes| debounce[Wait ~600 ms after last keystroke]
  debounce --> grammar{Grammar OK and non-empty?}
  grammar -->|No| noCommit[No bank write]
  grammar -->|Yes| same{Draft equals active slot S?}
  same -->|Yes| noCommit
  same -->|No| commit[Write to active slot S in app bank]
  commit --> ui[Green border + success banner + save config]

Auto-save off (default)​

  • Only the current runner/miner row changes.
  • Other preset slots in [app] stay as they were.
  • Switching slots loads the bank text into the editor without writing your draft into the clicked slot.

Auto-save on​

After you stop typing for about 600 ms, the app may commit only if:

  1. A preset slot is already selected (active slot S).
  2. FFmpeg / yt-dlp grammar checks pass.
  3. The draft is non-empty and differs from what is stored in slot S (normalized comparison).
  4. The draft is not already stored in a different slot (duplicate options are not auto-written).

On success:

  • Slot S in the bank is updated (label is re-suggested when needed).
  • The options editor gets a green border for a few seconds.
  • A success banner appears: Selected preset has been updated.
  • Config is saved (debounced).

Important: auto-save always writes to the slot that was selected before you edited (active_preset_slot / miner_active_preset_slot), never to a slot you only clicked afterward.

Clicking a preset slot​

ClickWhat happens
Plain click slot BLoad B into the editor (row draft). Does not write the bank.
Ctrl+click slot NModal: Write these options into slot N? Yes writes the current editor text into N.
Ctrl+Shift+click (Runners)Adds/cycles the FFmpeg preset chain (up to 3), when chaining is enabled in Settings.

Clicking B never silently overwrites B. Writing a slot is always Ctrl+click plus confirm.

Add preset, wizard, and other actions​

ActionBehavior
Add (+) slotOpens wizard if empty/duplicate; otherwise creates a new bank slot with unique options
Double-click slotOpens preset wizard for that slot
Drag preset chipsReorders slots in the bank
Preset wizard → CreateExplicit save into the chosen slot

Apply preset (bulk load) still loads into the editor without rewriting the bank.

Visual feedback​

SignalMeaning
Green border on FFmpeg / yt-dlp editorActive slot was just saved to the bank
Banner above options rowSelected preset has been updated.
Write-slot modalCtrl+click: confirm writing the current options into that slot

Related settings​

  • Coordination → Process files on FFmpeg change — file stats / re-processing when options change.
  • Coordination → Allow runner FFmpeg preset chain — Ctrl+Shift+click multi-preset queue on Runners only.
