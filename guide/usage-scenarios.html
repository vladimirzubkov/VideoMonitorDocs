Usage Scenarios

Practical workflows. Adjust paths, letters, and options to your setup.

Scenario 1: Nightly folder encode (watch mode)​

Goal: Everything matching *.mp4 under D:\Inbox becomes H.264 in D:\Inbox\VM@720p, including files that arrive overnight.

  1. Runner A — Path D:\Inbox, mask *.mp4, FFmpeg -c:v libx264 -crf 23, output subdir VM@720p.
  2. Settings → Coordination — enable Monitor unprocessed files (or press M on Runners with F2 shortcuts on).
  3. Start runner A. Leave Sequential or Parallel per taste (F2: S / P).
  4. Minimize to tray. New files are picked up on the next scan cycle.

Tip: Enable Process files on FFmpeg change only if you intentionally want re-encode when you edit options; otherwise changing CRF mid-run can mark existing outputs for overwrite (see Runners file stats line).

Scenario 2: Encode exactly five clips (manual queue)​

Goal: No folder scan — only chosen files, in a fixed order.

  1. Runner B — set path to the folder that contains the files (mask still applies to adds).
  2. Select files… (or Ctrl+Shift+Enter) and pick the five files.
  3. Reorder in the Selected files table: drag rows, or Ctrl+↑/↓ to move selection (contiguous block moves one step; non-contiguous selection compacts first).
  4. Start. The worker processes the list top to bottom; watcher mode does not refill from disk until you clear or change the list.

Tip: Ctrl+Shift+Space focuses the manual queue when it is non-empty. Right-click a row for Tag as processed (VM@: skip) to skip files without deleting them.

Scenario 3: Export playlists for a player (no transcode)​

Goal: Build M3U/M3U8 from runner sources for VLC, car unit, etc.

  1. Configure runner sources (directory scan or manual list).
  2. On Runners tab, hold Ctrl+Space — each row shows Playlist instead of Start.
  3. Click Playlist on one or more runners. Exports run in a background queue (FIFO): while one playlist is built, you can queue more; progress strip shows active job and “N more in queue”.
  4. Release Ctrl+Space to hide the buttons again.

Playlist path/format come from Settings → Coordination (playlist format, M3U8 filename pattern) and per-runner output layout. No FFmpeg encode runs for this action.

Scenario 4: Download a YouTube channel, then encode​

Goal: yt-dlp pulls into D:\DL\Channel; runner encodes to D:\Out.

  1. Miner C — Src URL https://www.youtube.com/@…, Destination D:\DL\Channel, set yt-dlp options (format, subs) via presets.
  2. Drill — queue fills (verify → scan → download). Review Download queue chips; click shared format tokens to paste into yt-dlp field.
  3. Runner D — Path D:\DL\Channel, mask *.mp4, destination elsewhere.
  4. Settings → Coordination — link miner C to runner D; optionally auto-start linked runner when miner batch completes.
  5. Start miner, then runner (or rely on auto-start).

Tip: When a URL title is first resolved, the sanitized folder name may copy to the clipboard and flash in the status bar — useful when naming the destination folder.

Scenario 5: Local folder of .url shortcuts​

Goal: A directory of browser link files, not a single channel URL.

  1. Miner — Src path = folder containing .url / .webloc / .desktop shortcuts (or drop one shortcut onto the miner row with drag-and-drop enabled).
  2. Drill — listing walks the tree (respecting skip dirs like .git, node_modules).
  3. Or drop a .m3u / .m3u8 onto the miner row for playlist expansion.

Scenario 6: CPU-constrained daytime encode​

Goal: Do not saturate the machine during work hours.

  1. Settings → CPU — set CPU limit (e.g. 40%). Enable Adaptive load to nudge effective cap within min/max while jobs run.
  2. Optional Start when lower — new encodes wait until system CPU stays below the limit for 5 seconds.
  3. Settings → App behavior → Work schedule — restrict runner activity to evening windows (orange Scheduled under tab when outside window).

Scenario 7: Low disk space on the encode volume​

Goal: When free space drops, delete oldest/largest sacrificial files from agreed trees.

  1. Settings → App behavior → Disk space cleanup — enable, set threshold and deletion preferences.
  2. On each runner row, enable Disk participation and choose Originals vs Outputs sacrifice.
  3. Hazard stripes on the row border indicate what may be deleted (orange originals, green outputs).

Use only when you understand which trees are shared and backed up.

Scenario 8: Remote UNC library​

Goal: Source or destination on \\server\share\… without treating brief disconnects as hard failures.

  1. Path vitality — enable in VideoMonitor.toml (path_vitality_*), prefer remote-only, tune probe interval and confirm failures.
  2. While Suspect, encode/download pauses without counting as permanent failure; Down triggers failure notifications.

Scenario 9: Telegram when a batch finishes​

Goal: Message on completion, Morse beep optional.

  1. Settings → Notifications — Telegram token/chat, templates with placeholders (%runner%, %files_count%, …).
  2. Per runner/miner Notify column — enable channels; all-off with sound-only still uses green styling for “sound only”.
  3. Edit sound for Morse templates (success vs failure differ).

Store tokens in VideoMonitor.local.toml on shared configs.

Scenario 10: Hide Performance tab until needed​

Goal: More space for Runners/Miners daily; charts only sometimes.

  1. Open Performance, uncheck Show Performance tab (pin on tab) or Ctrl+W while on Performance.
  2. Ctrl+Shift+T restores the tab in the strip without switching to it — stay on Runners and open Performance when ready.
