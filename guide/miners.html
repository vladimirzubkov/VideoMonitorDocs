Miners

A miner downloads video through yt-dlp. The source field is either an http / https link or a directory. Browse picks a directory, not a single file. A path to one file in that field is not walked by Drill.

Link files live inside a directory. The miner walks the tree and picks up .url, .webloc, .desktop shortcuts, .m3u / .m3u8 playlists, and text files that match the mask (out of the box *.url). You can drop a shortcut onto the row: the source becomes the URL itself. Drop a file of links or a playlist, and the source becomes its parent directory.

Where downloads go: if the destination directory is empty, the video lands next to the address file. You can set another directory — everything goes there. For a source tree there is a Preserve dir structure when downloading checkbox: the layout of directories with shortcuts is then mirrored under the destination. A URL source has no such checkbox: there is no tree.

Drill builds a queue and starts the download. yt-dlp options go in the row. Under that is a preset bank: a click fills in a ready-made option. To save your own text into a slot, hold Ctrl and click the preset.

How a download runs​

After Drill the program goes through:

collect the list → check the queue → download
  • Collect the list: a local directory is walked, skipping system folders (.git, node_modules, and the like). Links come from shortcuts, playlists, .vmtxt files, and PL... file names. Each link is one queue job.
  • Check the queue: for each row yt-dlp asks for the full description (-J): title, duration, video and audio formats, subtitles for the table. The miner row often shows progress such as "checking source: 3 of 12".
  • Download: a normal yt-dlp run down the queue. Progress is on the miner row or on the Performance tab.

While the queue check is running, the row shows Download now and Stop. Download now starts downloading from what is already known, without waiting for the rest of the check. Pause applies once yt-dlp is already downloading a file: the process is held. Resume continues the check or the download.

Inside the download queue​

  • The table shows Video and Audio chips for the resolutions and audio bitrates that are available. Formats shared by every video in the list are bold. Click a chip to put that format into the yt-dlp options line.
  • Subtitles: open the section and pick languages. The app folds them into one --sub-langs argument.
  • Columns can be sorted. The table is also moved with the keyboard (arrows or Tab).

Sequential queue​

Like runners, miners can run one at a time. The reason is different: not to take the whole network link, while runners are kept from taking the whole CPU. Miners started later wait with the status Queued.

Linking straight to a runner​

A miner can be linked to a runner: on the miner row you pick the runner's letter. When the download finishes, the linked runner picks up the downloaded files, if that is allowed in Settings → Coordination. Several miners can be linked to one runner, and that runner encodes the downloads one after another.

Incomplete format warning (stream matching)​

If the yt-dlp options would download video with no audio, or audio with no video, the program warns you. It can add the missing stream so you get a full file, or you can continue as written.

Presets​

Miner presets are a shared bank of yt-dlp format strings. A click loads the slot into the selected miner. The program ships six presets. There is no separate 360p slot. Reset miner presets puts this set back.

Miners do not chain presets. A chain of up to five is a runner feature.
