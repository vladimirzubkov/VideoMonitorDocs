Runners

A runner is one FFmpeg job. You say where the files are, how to process them, and where to put the result.

On the Runners tab each row has an options field and a preset bank. A click on a preset fills in a ready-made FFmpeg command. You can type your own command in the same field. To save it, hold Ctrl and click the preset. The program checks whether the command is valid, and if it is fine — writes it into the chosen preset.

FFmpeg and ffprobe must be on the system PATH. Without them a runner will not start. Whether FFmpeg is installed, where it came from, and which version it is, shows under the header of the runners window. VideoMonitor can install FFmpeg from inside the program: open the Settings tab; in the Libraries block at the bottom of the window, next to the message that FFmpeg is not installed, there will be an Install button.

For the install we recommend a package manager, for example Scoop. It helps you install and update the tools you need, including FFmpeg, and it takes care of the system PATH: checking, adding, and removing entries.

How to run your first job​

  1. Open Runners and pick a row, for example A.
  2. Set the directory with the source files and a mask of files to process, for example *.mp4. Filename fragments work too; you can write several conditions separated by commas or spaces.
  3. Pick a preset or type the FFmpeg options.
  4. Set where the finished files should go.
  5. Press Start.

The status column at the bottom shows what the runner is doing right now: watching the directory, encoding, waiting in the queue, or paused.

Whatever you change on screen, the program writes into VideoMonitor.toml next to itself. You can edit this file by hand: the program picks up the new settings at once, or on the next launch if it is not running.

Sequential and parallel execution​

In sequential mode only one runner runs. The others wait in the order they were started.

Parallel mode lets several runners work at once. Load can be limited by each runner's priority or by the CPU cap, so the computer stays usable. The simplest cap is a count of cores. A percent cap is also there, but it is only a rough limit, because the process cannot be controlled completely.

Metadata and the "processed" tag​

Output files get comment tags that start with VM@. In the handmade file table those rows look faded and carry an @. The comment also stores the FFmpeg compression options that were used.

Files VideoMonitor has already processed carry this @VM metadata tag in the description, so they are not processed again even if they land back in the originals folder. To work on individual files, open their list. It appears when you pick files with Select files… to the right of the mask, or with Show queue after the runner has scanned the directory, next to the originals path. There you can clear the VM@ mark, or mark files that have not been processed yet so the runner skips them.

Right-click a media row and choose mark as processed, clear the processed mark, or remove from the list.

An orange tint means the file already has a result whose options do not match the current FFmpeg arguments, so it may be encoded again (that depends on the settings).

Schedule​

If encoding should run on weekends or at night, set a schedule. Outside the allowed hours the runner shows as Scheduled in orange and waits. FFmpeg does not start. An encode that is already running may pause, depending on the "outside the window" setting.

The windows are in Settings → App behavior → Deferred actions. They apply to runners first, and the same conditions can be put on miners. They are program-wide. Separate schedules for runners and miners, or a schedule per row, are not available, and a per-row schedule is probably not worth building.

Playlists for a directory (no encoding)​

This is not on screen until you ask for it. On the Runners tab, hold Ctrl+Space. Start becomes Playlist on every row. A click writes a playlist for the directory and its subdirectories from that runner's settings. The playlist format is chosen in Settings, for example M3U8. FFmpeg does not encode while the playlist is written.

Presets​

Runner presets are a shared bank of FFmpeg commands. A click loads the slot into the selected runner. The bank itself changes when you save, or when auto-save is on. The program ships 14 presets. Reset runner presets puts this set back.

Double-click an existing slot to edit it in the preset wizard. The wizard builds the FFmpeg options for a slot: codec, container, quality, audio, and filters, including combinations (letterbox with edge blur, stabilize, denoise, loudness). Auto picks how hard to compress each file from its quality and from the minimum and maximum compression bounds you set (this is a VideoMonitor option, not an FFmpeg one). Heavy filters are split across the Options tabs.

The + slot is a new preset, and that is when the wizard suggests a name.

Ctrl+Shift+click builds a chain of up to five presets. Each preset runs its own tabs first, then the next preset. One preset holds up to three option tabs.
